# i18n — A1 (UI shell) + A3 (SEO meta)

**Date:** 2026-05-02
**Project:** modestshop.md internationalization
**Phase:** Sub-project A — A1 + A3 (A2 product DB content deferred)
**Status:** spec

## Goal

Internationalize the customer-facing surface of modestshop.md across **Romanian (RO)**, **Russian (RU)**, and **English (EN)**. Deliver path-prefixed URLs (`/ro/...`, `/ru/...`, `/en/...`), a header/footer language switcher, and full per-page SEO metadata with `hreflang` alternates. Romanian remains the source of truth.

## Brand spine

The redesign's "Eleganta nu se striga" carries through translation: copy stays restrained, no shouty marketing voice in any language. RU and EN translations match the RO tone — quiet, declarative, never breathless.

## Scope

### In scope (A1 + A3)

- All customer-facing pages: Home, Shop, PDP, Discovery (landing + detail), Checkout, Order, About, Contact, FAQ, Privacy, Terms, Careers, Login, NotFound
- Header, footer, cart sheet, search overlay, brand wall, toasts, generic CTAs
- Form labels, validation messages, button states
- Per-page SEO meta: `<title>`, `<meta name="description">`, OpenGraph locale, canonical, `hreflang` alternates including `x-default`
- `<html lang>` attribute synced to the active locale
- EU country labels (27 countries) — RU + EN strings added alongside the existing RO labels in `src/utils/vat.ts`'s display path
- Path-prefixed routing (`/ro/*`, `/ru/*`, `/en/*`) with bare `/` redirecting to `/ro`
- Language switcher in header **and** footer
- All internal links localized via a `useLocalizedHref` helper

### Out of scope (deferred to A2)

- Product names, brand names, fragrance notes, descriptions stored in Supabase
- SKU display labels and category names from DB
- Reviews and any future user-generated content
- Admin pages — admin remains Romanian-only (Phase 4 was cut; admin is Romanian by design)
- `sitemap.xml` generation (follow-up if organic traffic warrants)
- Currency/number/date locale formatting beyond what the existing helpers already handle (MDL formatting unchanged; EUR formatting unchanged)
- Email templates (no transactional email — order confirmations go through WhatsApp/Telegram)

## Decisions captured

1. **A1 + A3 only** — UI shell strings + SEO meta. A2 (product DB translations) deferred.
2. **3 locales** — RO (default), RU, EN.
3. **Path-prefixed routes** for all three locales. URL is canonical.
4. **`react-i18next`** as the i18n library. JSON namespaces, flat keys.
5. **URL is the sole source of truth** for the active locale. Bare `/` redirects to `/ro`. No browser-language sniffing, no localStorage.
6. **Language switcher in header + footer** — same component, two layout variants.
7. **Customer-facing only** — admin pages stay Romanian; auth flows are in scope (Login).

## Architecture

### Library stack

- `i18next` (core)
- `react-i18next` (React bindings)
- `react-helmet-async` (per-page meta tags)

`i18next-browser-languagedetector` is **not** installed — URL is the only source.

### Configuration entry point

New file `src/i18n/index.ts`:
- Initializes i18next with `react-i18next`
- Loads all namespaces eagerly (the bundle is small enough that lazy loading isn't worth the complexity)
- Sets `fallbackLng: 'ro'` so missing keys in RU/EN fall back to RO instead of showing the raw key
- Sets `defaultNS: 'common'`
- Sets `interpolation.escapeValue: false` (React already escapes)

`main.tsx` imports the config so i18next is initialized before React renders.

### Translation file layout

```
src/i18n/
  index.ts                 # i18next setup
  locales/
    ro/
      common.json
      home.json
      shop.json
      product.json
      discovery.json
      checkout.json
      order.json
      static.json
    ru/
      ... (same files, same keys)
    en/
      ... (same files, same keys)
```

Romanian is the source of truth. RU and EN files are written by translating the RO files, preserving the same key structure. Missing keys fall back to RO.

### Routing

`App.tsx` route tree changes:

```
/                              → <Navigate to="/ro" replace />
/:lang/*                       → <LanguageGate>
  /:lang                       → Index
  /:lang/shop                  → Shop
  /:lang/product/:id           → Product
  /:lang/discovery-sets        → DiscoverySets
  /:lang/discovery-set/:id     → DiscoverySet
  /:lang/checkout              → Checkout
  /:lang/orders/:orderId       → OrderConfirmation
  /:lang/about                 → About
  /:lang/contact               → Contact
  /:lang/faq                   → FAQ
  /:lang/privacy               → Privacy
  /:lang/terms                 → Terms
  /:lang/careers               → Careers
  /:lang/login                 → Login
  /:lang/admin/*               → Admin (RO content regardless of :lang)
  /:lang/admin/orders/:orderId → AdminOrder (RO content regardless of :lang)
  /:lang/*                     → NotFound
```

The catch-all `<Route path="*" element={<NotFound />}>` stays inside `/:lang/*`. `<LanguageGate>` itself validates the `:lang` segment — any unrecognized prefix (`/xyz/...`) is redirected to `/ro/xyz/...` from inside the gate, so no separate top-level catch-all redirect is needed. The bare-root `<Route path="/" element={<Navigate to="/ro" replace />}>` is the only special case.

### `<LanguageGate>` component

`src/components/LanguageGate.tsx`:
- Reads `:lang` from `useParams()`
- If `lang` is not in `['ro', 'ru', 'en']`, renders `<Navigate to={`/ro/${restOfPath}`} replace />`
- On mount and on `lang` change, calls `i18n.changeLanguage(lang)` and sets `document.documentElement.lang = lang`
- Renders `<Outlet />`

### `useLocalizedHref` hook

`src/hooks/useLocalizedHref.ts`:

```ts
export function useLocalizedHref() {
  const { i18n } = useTranslation();
  return (path: string) => `/${i18n.language}${path.startsWith('/') ? path : `/${path}`}`;
}
```

Used as: `const href = useLocalizedHref(); <Link to={href('/shop')}>`. The full sweep replaces every `<Link to="/shop">` and `navigate('/shop')` call with the localized form.

### Language switcher

`src/components/LanguageSwitcher.tsx`:
- Props: `variant: 'header' | 'footer'`
- Renders three buttons: `RO · RU · EN`
- Active locale uses `text-strong`; inactive use `text-muted` with `hover:text-text` and `transition-colors duration-quick ease-default`
- Click → `useLocation()` to grab current `pathname` + `search` + `hash`, swap leading `/<lang>/` for `/<newLang>/`, navigate to result
- Header variant: compact horizontal pills, between search icon and cart icon
- Footer variant: same pills, larger tap targets, in the footer's right column above legal links
- On mobile (< `md`), the header switcher collapses into the existing menu sheet as a row at the top

### `<html lang>` attribute

Updated by `<LanguageGate>` via `document.documentElement.lang = lang`. This is what screen readers and Google's language detection use.

### SEO meta

`src/hooks/usePageMeta.ts`:

```ts
usePageMeta({
  titleKey: 'meta.title',
  descriptionKey: 'meta.description',
  namespace: 'shop',
});
```

Behind the scenes uses `react-helmet-async` to inject:
- `<title>{t(titleKey)} · ModestShop</title>`
- `<meta name="description" content={t(descriptionKey)}>`
- `<meta property="og:title" content={...}>`
- `<meta property="og:description" content={...}>`
- `<meta property="og:locale" content="ro_MD" | "ru_RU" | "en_US">`
- `<link rel="canonical" href="https://modestshop.md/<lang><pathname>">`
- `<link rel="alternate" hreflang="ro" href="https://modestshop.md/ro<pathname>">`
- `<link rel="alternate" hreflang="ru" href="https://modestshop.md/ru<pathname>">`
- `<link rel="alternate" hreflang="en" href="https://modestshop.md/en<pathname>">`
- `<link rel="alternate" hreflang="x-default" href="https://modestshop.md/ro<pathname>">`

`pathname` here means the **language-stripped** path (`/shop`, `/product/abc`, etc.) — the hook computes alternates by re-prefixing for each locale.

`HelmetProvider` wraps the app in `main.tsx`.

### Per-page meta keys

Each page namespace includes a `meta` block:

```json
{
  "meta": {
    "title": "Magazin",
    "description": "Parfumuri rare și de nișă, livrate în Moldova și UE."
  }
}
```

PDP and Discovery-set detail templates use interpolation:

```json
{
  "meta": {
    "title": "{{name}} — {{brand}}",
    "description": "{{name}} de {{brand}}. Decanturi de la 2ml. Livrare în Moldova și UE."
  }
}
```

(Product `name` and `brand` come from DB. They display untranslated in this phase — A2 will translate the data layer.)

## Translation file format & key conventions

- **Flat JSON, two-level nesting max** per namespace
- **Keys describe purpose**, not the source string. `checkout.submit`, not `checkout.placeOrder`
- **Interpolation**: `{{name}}` syntax (i18next default)
- **Pluralization**: i18next `_one` / `_other` suffixes where Romanian or Russian require different forms
- **No string concatenation in components**: `t('shop.productsCount', { count })` always, never `t(...) + count`
- **Romanian is the source of truth** — all keys exist in `ro/*.json` first, then RU/EN translate to match

### Country labels

`common.json` carries a `countries` block keyed by ISO-2 code:

```json
{
  "countries": {
    "MD": "Moldova",
    "RO": "România",
    "DE": "Germania",
    "FR": "Franța",
    ...
  }
}
```

`src/utils/vat.ts` (or a thin wrapper in `src/utils/countries.ts`) gains a `getCountryLabel(code: string, t: TFunction): string` helper. Country `<Select>` options in checkout call this helper.

## Sweep order (implementation phases)

1. **Foundation:** install deps; create `i18n/index.ts`; create `<LanguageGate>`; rewrite `App.tsx` routing; create `useLocalizedHref`; wire `<HelmetProvider>` in `main.tsx`. Build passes with empty translation files.
2. **`common` + chrome:** populate `common.json` (RO/RU/EN); migrate Header, Footer, CartSheet, SearchOverlay, BrandWall, toasts; create `<LanguageSwitcher>`; mount it in Header and Footer.
3. **`home`:** populate `home.json`; migrate Index, DiscoveryCTA, NewArrivalsCarousel.
4. **`shop`:** populate `shop.json`; migrate Shop, FilterSidebar, ProductsView, BrandsView.
5. **`product`:** populate `product.json`; migrate Product page and all `product/*` components.
6. **`discovery`:** populate `discovery.json`; migrate both discovery pages and all `discovery/*` components.
7. **`checkout`:** populate `checkout.json`; migrate Checkout, CheckoutForm, OrderSummary, MobileSubmitBar, ShippingEstimate, ShippingEstimateForCart; add country labels helper.
8. **`order`:** populate `order.json`; migrate OrderConfirmation (both `?placed=1` and bare modes).
9. **`static`:** populate `static.json`; migrate About, Contact, FAQ, Privacy, Terms, Careers, Login, NotFound.
10. **SEO meta:** create `usePageMeta`; wire on every customer-facing page; populate `meta` blocks in all 8 namespaces × 3 locales.
11. **Build verify** (`npm run build`); hand off to user for manual QA across the three locales.

After each phase, `npm run build` must pass. RU and EN files are populated *with* their RO siblings within the same phase — no phase ends with empty translations.

## Verification

- `npm run build` passes after every phase
- Visiting `/`, `/ro`, `/ru`, `/en` lands on Home in the right language
- Visiting `/xyz` redirects to `/ro/xyz` (which itself 404s correctly)
- Switching language in the header preserves the current page and query string
- View source on each page shows correct `<title>`, `<meta name="description">`, four `<link rel="alternate" hreflang>` tags, and matching `<html lang>`
- No raw translation keys visible anywhere on the customer-facing surface
- Admin pages render Romanian regardless of URL `:lang` prefix

## Risk register

- **Translation accuracy:** RU and EN are written by the implementer (or follow-up translator) from RO. Tone-matching the brand spine is harder than literal translation. Mitigation: keep keys narrow in scope; let the translator see one namespace at a time.
- **Broken internal links:** Every `<Link to="/shop">` not migrated to `useLocalizedHref` will drop the user out of their language. Mitigation: per-phase grep for unprefixed `to="/` and `navigate("/` after migration.
- **SEO transition:** Existing organic traffic to `modestshop.md/shop` (no prefix) will redirect to `/ro/shop`. Mitigation: 301 redirects in Vercel config (single-line `vercel.json` route entry); preserves link equity.
- **Admin URL drift:** Admin URLs gain a `:lang` prefix (`/ro/admin/...`). Bookmarks break once. Acceptable cost.
